# 模板改造为 vibe-init 技能

- 日期：2026-10-17
- 状态：已生效
- 相关模块：`skills/vibe-init/`（SKILL.md、assets/、scripts/）、根 `README.md`、根 `AGENTS.md`

## 决策内容

模板从「根目录文件 + 手工复制接入」改造为 skill 交付：模板唯一正本迁入 `skills/vibe-init/assets/`，接入动作为触发 vibe-init 技能 → 脚手架脚本生成骨架 → Agent 逐节引导填占位符；本仓库不再保留根目录模板副本，自身治理改用精简根 AGENTS.md + `docs/decisions/`。

## 选择理由

- 一键初始化：触发词即可在新项目生成完整治理骨架，消除手工复制漏文件/漏替换的出错面。
- 引导填写质量更高：占位符由 Agent 按"先代码自查、查不到才问人"逐节补齐，优于裸模板让人自填。
- 为后续治理技能（如 vibe-memory：记忆/决策写作细则 + 双预算校验脚本）预留组合空间；红线常驻 AGENTS.md、操作细则按需进 skill 的分工就此定型。
- 消除双正本：assets 即唯一正本，仓库根不再存模板副本，杜绝两处分叉。

## 被否决的替代方案

| 方案 | 否决原因 |
| --- | --- |
| 根目录保留模板、skill 脚本引用仓库根路径 | 跨机器路径脆弱；模板与 skill 内容两处维护，必然分叉 |
| 占位符由脚本交互式收集（命令行问答） | 访谈逻辑写死进脚本；Agent 层引导更灵活，且与 interview-me 类技能可组合 |

## 影响范围

- 涉及文件/模块：根 `AGENTS.md`、`docs/*` 迁入 `skills/vibe-init/assets/`；根 `README.md` 重写为仓库说明书；新增本仓库 `docs/decisions/`。
- 兼容性影响：已按旧方式接入的项目不受影响（产出物相同）；后续接入统一走 skill。
- 后续约束：改模板只改 assets 并先登记决策；本仓库自身决策记录在根 `docs/decisions/`，与模板内示例区分。

### 追记 2026-10-17

实测反馈（~/test 空仓测试）：初始化时逐节追问占位符（§1 定位/技术栈/入口）在空仓场景无信息可查，追问价值低且打断冷启动。修订为：生成骨架即结束、不向用户追问；占位符重新定位为「待回填区」，由 Agent 在开发过程中获知实际信息后主动替换。同步修订：assets/AGENTS.md 头部说明、SKILL.md 工作流程第 3/4 步与红线（初始化禁止追问）、脚本 docstring 与尾提示。性质：流程小修（追记），非方向推翻。
