# vibe-governance — 治理维护与复盘

治理体系"修改自身"的细则。分工边界：骨架生成归 vibe-init，L2/L3 写作细则归 vibe-memory；本技能只管 L1（AGENTS.md 与模板规则）的演化——何时修、怎么裁决、怎么留痕。

## 触发场景与路由

| 场景 | 读哪份细则 |
| --- | --- |
| 增删改协作规则（AGENTS.md 或模板文件） | `references/l1-maintenance.md` |
| 治理复盘（信号出现 / 用户要求） | `references/governance-review.md` |
| 规则冲突裁决 | 两份都读（优先级链在 l1-maintenance） |

## 复盘触发信号（任一即触发；正本见项目内 `docs/design/governance-retrospective.md`）

1. 任一记忆文件超双预算，或为守行数开始写 200+ 字符长行
2. 决策索引超过一屏（~50 条）仍未建立或停止维护
3. 同一主题的决策记录被追记超过 3 次
4. 同一条规则在两处出现且表述开始分叉
5. 收尾三件套（context / progress / 决策记录）开始被跳过或敷衍

## 工作流程

1. 判定场景：单条规则的增删改 → 走 `l1-maintenance.md` 修订流程；系统性问题（多个症状并发、同一根因）→ 走 `governance-review.md` 复盘流程。
2. 修订落地的每一处规则变更，登记决策记录（决策怎么写见 vibe-memory 细则）。
3. 收尾验证：模板改动复跑 vibe-init 脚手架回归 + 官方打包校验，展示输出。

## 红线

- 复盘产出物固定为「问题→证据→改法」清单 + 逐条裁决（采纳/否决/改写）；没有运行痕迹证据的体感不入清单。
- 方向性推翻已有决策须先建新决策记录并互相引用，不得直接改规则文件了事。
- 规则变更只写唯一对应位置，写入前先查重；本技能产出的细则同样受此约束。
