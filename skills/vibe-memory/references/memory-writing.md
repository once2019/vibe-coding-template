# L3 会话记忆写作细则

> 上半 = context.md（状态快照）；下半 = handoff.md（跨会话交接）。
> 红线与双预算见 AGENTS.md §5；本文件只写"怎么填才合格"的判断细则。
> 出处：`docs/design/governance-retrospective.md` 反模式 #2/#3/#6/#8 及各文件头部说明。

## context.md — 项目状态快照

### 语义铁律：状态，不是日志

快照回答"项目现在什么状态"，不回答"过去发生了什么"。历史归属两处：决策过程进 `docs/decisions/`，执行过程进 `docs/progress/`。

合格与病态对照：

| 区块 | 合格 | 病态 |
| --- | --- | --- |
| 本会话已完成 | 「lake REST API 上线，消费契约规格定稿」 | 「今天先调研了 httpx，然后试了…（过程叙事）」；或上一会话的条目还留着 |
| 进行中任务 | 「backfill 分片逻辑：分片边界未定，阻塞于决策 2026-10-15」 | 只写任务名不写状态与阻塞 |
| 下一步计划 | 动词开头、按优先级、可直接开工 | 「继续完善」（不可判定） |
| 阻塞问题 | 写明阻塞物与解除条件 | 有阻塞却写"无" |

### 收敛纪律

- 完成项移交 `docs/progress/`（`YYYY-MM-DD-任务名.md`，含任务描述/完成状态/验证方式/遗留问题）后，**立即从快照删除**——不移交不删除是流水账的成因。
- 关键决策索引只列最近 3 条文件名，不写摘要（摘要在 `decisions/README.md`）；被顶掉的条目自然沉入决策索引，不丢失。
- 「最后更新」行必须带日期时间与一行会话标识（本次会话做了什么），这是并行会话判断新鲜度的唯一依据。

### 更新写法

- 终态是重写整个快照；同仓并行会话时执行顺序 = 先读最新版 → 精确片段替换落地。禁止无脑整文件覆盖（会冲掉并行会话刚写的状态），也禁止原地追加（破坏快照语义）。
- 双预算（≤40 行且单行 ≤150 字符）超出时先裁剪：删历史、并条目、砍叙事，再写入。

## handoff.md — 跨会话交接

### 语义：给下一个会话的接手说明书

读者是"对本项目一无所知、只知道要接着干"的新会话 Agent。检验标准：新会话读完 context + handoff + 最近 3 条决策，不问人就敢动手。

### 分区要求

- **运行态**：只放易腐条目（pid、后台任务、时限纪律、"XX 之前勿动"类临时禁令）。每条**必须带失效条件**（日期或事件，如「任务结束即失效」）；更新本文件时先清掉已失效条目。交接知识严禁混入此区（反模式 #6 的直接成因）。
- **已完成工作摘要**：按模块或任务写结果，不写过程；一屏内。
- **未完成工作清单**：checkbox + 当前状态 + 建议的下一步——新会话按此直接接手，写成「未完成清单为本会话首批任务」（AGENTS.md §5 红线的执行依据）。
- **关键决策引用**：链接决策文件 + 一句话强调「新会话不得在未读这些记录的情况下修改相关模块」；只列本次会话产生或触碰的决策，不做全量罗列。
- **新会话必须遵守的约束**：只写**读代码看不出来的**——临时 workaround 及原因、环境坑、需人类确认后才能动的事项（Ask-first 事项指向 AGENTS.md §4 清单，不复制清单本身）。

### 触发与分工

- 会话收尾必写，无例外（反模式 #8 的裁决：删掉不可测的"上下文 70%"条款后，这是唯一触发条件，成本由双预算控制 ≤60 行）。
- 与 context.md 的分工：context 是**项目当前状态的自照**（谁读都是这个状态）；handoff 是**本次会话向后传递的包裹**（会话特有：运行态、交接摘要、收尾约束）。两者重叠时，交接信息以 handoff 为准，context 收敛到纯状态。
- 里程碑完成也可触发撰写（交接原因注明），不必等到收尾。
